# Korean Core Starter — UI/UX Rebuild Design

**Date:** 2026-05-30
**Status:** Approved design → ready for implementation plan
**Scope:** Full front-end rebuild. The content/data layer is reused unchanged.

---

## 1. Context & goal

Korean Core Starter is a beginner Korean learning web app for English speakers (built for the author to share with friends). The **content is rich and solid**: 920 words, 78 expressions, 50 patterns, 40 grammar points, an 11-chapter course, a newcomer survival guide, and 12 situational dialogues — all generated by `scripts/*.mjs` into JSON under `korean/data/`.

The **front end has accumulated problems**: a vanilla `app.js` (~2.3k lines) + `styles.css` (~1.8k lines) grown over many quick iterations, 6 flat top tabs, a filter rail that only works on one screen, recurring layout breakage, and a look that the author wants to feel like Duolingo. The decision is to **tear down and rebuild the UI** while keeping the data.

**Goal:** a clean, Duolingo-style, responsive learning app that (a) keeps our content depth, (b) adds the interactive, active-recall learning Duolingo does well, and (c) is easy to maintain.

## 2. Decisions (agreed)

| Axis | Decision |
|---|---|
| Look & feel | **Duolingo visual style** — vibrant color, big rounded cards, 3D buttons, lesson path, generous spacing, big touch targets |
| Game mechanics | **None** — no XP/streak/hearts/levels. Keep only a light "lesson complete" check + progress, stored in `localStorage` as a nav aid |
| Tech | **Vite + Svelte** SPA, hash routing, static build → GitHub Pages |
| Device | **Responsive** — bottom tab bar on mobile, left sidebar nav on desktop |
| Navigation | **5 destinations:** Learn · Practice · Talk · Dictionary · Guide |
| Data | **Reuse** the existing generator pipeline + JSON unchanged |

## 3. Learning-design improvements (from studying Duolingo's Korean course)

Duolingo is strong at interactive Hangul onboarding, active-recall exercises, and audio-first practice; it is weak at grammar explanation, real-life use, and deep retention. Our app is the inverse. The rebuild adopts Duolingo's strengths and **keeps our depth as the differentiator**:

1. **Interactive Hangul trainer** (new) — letter→sound (tap to hear), sound→letter, syllable building (초성+중성+종성 → 한), and letter/sound match-pairs. Replaces today's text-only Chapter 1.
2. **Active, audio-first exercise types** (new) — match-pairs, listen-and-choose (uses TTS), build-sentence-from-word-bank (tap tiles), dictation — added to the current recognition/fill-blank/form-transform set.
3. **Global romanization toggle** — romanization shown by default, with a prominent "hide romanization" switch to train Hangul reading (extends Talk's practice mode app-wide).
4. **Bite-sized lesson path** — each chapter split into small lesson nodes (vocab → grammar → practice → dialogue), completed one at a time.
5. **Keep & surface our advantages** — rich grammar/conjugation tips, real-life Talk dialogues, newcomer Guide. Quiz feedback shows the correct answer **plus a one-line reason** from our grammar data.
6. **(Optional, later) speaking practice** — Web Speech `ko-KR` recognition for "say it" self-check; flagged approximate.

## 4. Architecture

- **Vite + Svelte**, single-page app. **Hash routing** (`svelte-spa-router`) so GitHub Pages needs no server config. `vite.config.js` sets `base: '/words/'` (repo path).
- **Data is imported, not bundled by hand.** `scripts/generate-*.mjs` keep producing JSON in `korean/data/`. Vite imports those JSON files directly. `data-bundle.js` is retired.
- **Project structure:**
  ```
  src/
    main.js                 # mount App, init router
    App.svelte              # responsive shell: nav + <Router>
    routes/
      Learn.svelte  Practice.svelte  Talk.svelte  Dictionary.svelte  Guide.svelte
    lib/
      data.js               # imports JSON, builds entries[] + byId + findEntry, exposes chapters/dialogues/guide/grammar/activities
      audio.js              # Web Speech ko-KR TTS (speak), voice selection
      stores.js             # Svelte stores: romanizationVisible, filters, lessonProgress (localStorage)
      hangul.js             # jamo tables + syllable compose/decompose for the Hangul trainer
      quiz.js               # exercise generators (match, listen, word-bank, dictation, recognition, fill-blank)
    lib/components/
      Button3D  Card  Chip  ProgressBar  EntryCard  EntryDetail  AudioButton
      KoLine  RomanizationLine  Sheet  SearchBar  BottomNav  SideNav  ExerciseHost
    styles/tokens.css       # design-system variables + base
  korean/data/*.json        # unchanged, imported by lib/data.js
  ```
- **Build/deploy:** `npm run build` → `dist/` → GitHub Pages (gh-pages branch via `npm run deploy`, or `/docs`). Old `korean/` stays live until cutover.

## 5. Design system (`tokens.css`)

- **Color:** primary grass-green `#58cc02` (3D shadow `#46a302`), accent sky-blue `#1cb0f6`, warm bg `#f7faf5`, white cards, ink `#3c3c3c`; per-type accent hues (word/expr/pattern/grammar).
- **Shape/motion:** radii 16px (cards) / 999px (pills); **3D button** (fill + darker bottom border; press = `translateY`); gentle transitions; generous spacing.
- **Type:** Pretendard; bold friendly headings; large Korean with romanization beneath (toggle-able).
- **Components** listed in §4; all themeable via tokens.

## 6. App shell & navigation

- **Mobile:** sticky top app-bar (title + search) + **bottom tab bar** (5 icons), single column.
- **Desktop:** **left sidebar** (icon+label, active highlight) + centered content (max-width ~1120px). Search in the top bar opens a command palette.
- **Routes:** `/learn` (default) `/practice` `/talk` `/dictionary` `/guide`; deep links e.g. `/dictionary/word-verb-001` open detail.
- The old always-present filter rail is gone; filters live **inside Dictionary** only.

## 7. Screens

**Learn** — vertical **lesson path** of the 11 chapters as rounded nodes. Top: "Continue" (last-opened, localStorage) + a daily phrase. Each chapter expands to micro-lessons (vocab → grammar → practice → dialogue). **Chapter 0 = the interactive Hangul trainer.** A "Grammar reference" entry exposes the 40 grammar cards, grouped.

**Practice** — choose a deck (chapter / topic / all) and an exercise mode. **Exercise engine (`quiz.js` + `ExerciseHost`)** supports: match-pairs, listen-and-choose, word-bank sentence build, dictation, recognition (MC), fill-blank, form-transform, plus **Hangul drills**. Immediate feedback with correct answer + one-line reason. Simple results summary; no hearts.

**Talk** — 12 situational dialogues as cards → dialogue player: speaker pills, Korean + romanization + EN, per-line audio, **Practice mode** (hide EN), optional play-all.

**Dictionary** — search + filters (type / level / topic / POS) over all 920+ entries; `EntryCard` results; tap → rich **EntryDetail** sheet (verb forms panel, usage, examples, conjugation tips, mistakes, cross-links). Replaces today's Browse + detail modal + filter rail.

**Guide** — 4 newcomer tracks → units → unit detail (key phrases, dialogue, vocab links, steps, official deep-links). Reuses `guide.json`.

## 8. Shared components & data

- `lib/data.js` indexes the JSON once: `entries[]`, `byId`, `findEntry(id)`, plus `chapters`, `dialogues`, `guideTracks`, `grammar`, `activities`.
- `EntryDetail` and `EntryCard` are reused by Dictionary, Learn, Talk, Guide (single source of truth for rendering an entry).
- `AudioButton` + `lib/audio.js` wrap Web Speech `ko-KR` TTS.
- `stores.js` holds `romanizationVisible` (global toggle), Dictionary `filters`, and `lessonProgress` (completed lesson ids in localStorage).

## 9. Migration sequencing (phased; old app stays live until cutover)

1. Scaffold Vite+Svelte, tokens, responsive shell + nav, `lib/data` + `lib/audio`.
2. **Dictionary** (largest reuse of entry rendering) + EntryDetail.
3. **Learn** path + chapter view + **Hangul trainer** + Grammar reference.
4. **Practice** exercise engine (all exercise types).
5. **Talk** dialogue player.
6. **Guide**.
7. Global romanization toggle, polish, cutover deploy.

## 10. Verification (preview is unreliable in the dev sandbox)

- `npm run build` must pass; `npm run lint`/svelte-check clean.
- **Vitest + @testing-library/svelte** unit/component tests: `lib/data` (counts + `findEntry` + all cross-links resolve), `lib/hangul` (compose/decompose correctness), `lib/quiz` (each generator yields valid items), and smoke renders of each route.
- Existing `scripts/audit-korean-content.mjs` + generator stay as the data-integrity gate.
- **The author runs `npm run dev` in their own browser** for visual sign-off after each phase.

## 11. Risks & open questions

- **Scope is large** → strictly phased; each phase ships behind its own preview/sign-off. Hangul trainer and the exercise engine are the two biggest net-new builds.
- **GitHub Pages base path** must match the repo (`/words/`); hash routing avoids 404s on refresh.
- **Speech recognition** (improvement #6) is browser-dependent and unreliable → deferred to a later, optional phase.
- **Data shape**: a couple of homograph entries (눈 eye/snow, 다리 leg/bridge) intentionally duplicate headwords — Dictionary should disambiguate by gloss, not dedupe.
- **Cutover**: keep `korean/` reachable until the Svelte build is verified, then switch the deployed root.
