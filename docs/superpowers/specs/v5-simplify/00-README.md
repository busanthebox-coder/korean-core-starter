## 실측 (2026-07-20, 라이브 사이트 · 신규 사용자 상태 · 375px) — 이 트랙의 존재 이유

**세 불만 모두 실체가 확인됐다. 감이 아니라 데이터다.**

### ① 순서가 실제로 깨져 있다 (최우선)
- 표시 순서: 1~11과(A1) 다음이 **47(B1) → 24(B1) → 13(B1) → 26(B1) → 15(B1)** → 그 다음에야 A2.
  **과거형(A2)을 배우기 전에 Reported Speech(B1)가 먼저 온다.**
- 원인: `curriculumSortValue()`가 챕터의 `curriculumOrder` 필드를 그대로 신뢰하는데, 그 값이 레벨 순서와
  무관하게 뒤섞여 있음(`apply-curriculum-structure` 산출). "Next up" 추천이 이 순서의 첫 미완료 챕터를
  가리키므로, **A1을 끝낸 학습자에게 앱이 B1 챕터를 다음 할 일로 추천한다.**
- 챕터 번호도 표시 순서와 무관(40번이 과거형, 12번이 불규칙활용): 학습자가 "몇 과"로 위치를 가늠할 수 없다.

### ② 어려운 단어가 섞이는 진원지 (챕터가 아니라 Practice·Speak·Dictionary)
- **A1 챕터(1~11) 내부 어휘는 깨끗하다**(B급 혼입 1건: 설명하다). 챕터가 문제가 아니다.
- **Practice 기본 덱 = `all` = 전체 3,848개** (Practice.svelte `let deck = 'all'` → `return entries`).
  3일차 학습자가 Practice를 열면 B2·C1 단어로 퀴즈를 본다. ← "어려운 단어가 섞인다"의 주범.
- **Speak의 추천 섀도 = "Opening a Bank Account"(A2·은행)**: dialogues 배열이 레벨 정렬 없이 첫
  미완료를 추천 → 1일차 사용자의 첫 말하기가 계좌 개설.
- **Dictionary 기본 화면 = 3,848개 전부 렌더**(높이 680 화면분, 탭 가능 요소 3,901개). 기본 진입이 익사 체험.
- 챕터 단어 중 **21개가 사전 미등재**(주세요·얼마예요·부터·까지·그럼 등 초고빈도 포함) — 챕터에서 본 단어를
  사전에서 못 찾는다.

## 설계 원칙 (세 지시 공통)
1. **한 줄 경로**: 앱이 항상 "다음 하나"를 안다. 학습자가 고르는 건 예외 경로다.
2. **레벨 신호 하나, 세 군데 재사용**: 파생된 학습자 레벨(§공통 참조) 하나로 Practice 풀·Speak 추천·
   Guide 노출을 모두 거른다. 기능별 필터를 따로 만들지 않는다.
3. **잠금 금지, 숨김 우선** (기존 원칙 유지): B급 콘텐츠는 지우지도 잠그지도 않는다 — 기본 화면에서 안 보일 뿐,
   명시적 선택("모든 레벨 보기")으로 언제든 접근 가능.
4. **Learn은 이미 단순하다**: 이번 트랙에서 Learn 첫 화면·Hanmok 디자인은 손대지 않는다.

## 공통 참조 — 학습자 레벨 신호 `learnerLevel()`
- 정의: `max(배치테스트 결과(kcs.placement-v1, WS4 기존), 완료 챕터 중 최고 레벨)`. 신규 사용자는 A1.
- 위치: `src/lib/learnerLevel.js` 신설(순수 함수 + 테스트). **신규 저장 키 없음** — 기존 progress·placement에서 파생.
- "한 레벨 위까지 노출" 규칙: 필터 기본값은 `learnerLevel + 1`까지 (A1 학습자 → A1+A2 노출, B급 숨김).

## 하지 말 것 (트랙 공통)
- 챕터 **번호 재부여 금지** — id·번호는 SRS·진행도·링크가 물고 있다. 고치는 건 **정렬 순서**뿐.

- 자동 레벨 강등 금지 — learnerLevel은 올라가기만 한다(오답이 많다고 내려가지 않는다).
