# S1 — 한 줄 경로: 챕터 순서와 부제를 실제 학습 순서에 맞추기

규모: 중. 의존 없음.
목표 한 줄: A1부터 순서대로 따라가면 난이도가 한 번도 뒤로 가지 않게 만든다.

## 실측 근거 (2026-07-20) — 세 번 재측정한 결과

처음 두 번의 측정이 틀렸다. 기록을 남긴다:
1. **1차(틀림)**: `app-data.json`의 챕터 배열을 그대로 읽고 "11과 다음이 47과"라고 판단했다.
   그 배열은 저장 순서일 뿐이고, `data.js`는 `curriculumSortValue`로 정렬해서 쓴다.
2. **2차(틀림)**: 정렬 후 `curriculumTrack.cefr`을 보니 `A1×11 → A2×23 → B1×22 → B2×7 → C1×2`로 완벽했다.
   "순서 문제 없음"이라고 판단했다. 그러나 `curriculumTrack`은 **위치로 부여된 라벨**이라 자기 자신을 증명한다.
3. **3차(실측)**: 내용 난이도인 `level` 필드를 표시 순서에 대고 보니 —

| 실측 | 값 |
|---|---|
| 표시 순서 vs 내용 난이도 **역전쌍** | **185 / 2080 (8.9%)** |
| **과거형(A2)의 위치** | **40번째** |
| 과거형보다 먼저 나오는 B1 내용 챕터 | **12개** |
| 간접화법(-다고 했어요)의 위치 | 36번째 — **과거형보다 4과 먼저** |
| `level` ≠ `curriculumTrack.cefr` 인 챕터 | **21 / 65** |

간접화법은 과거형 없이는 성립하지 않는다. 이건 취향 문제가 아니라 순서 오류다.

### 왜 이렇게 됐나 (근본 원인)
`apply-curriculum-structure.mjs`가 `order[]`로 챕터를 재배열하면서 **번호를 다시 매긴다**(`number: position`).
그런데 같은 스크립트가 `curriculum-chapter-tone-overrides.json`을 **표시 번호로 조회**한다
(`chapterToneOverrides.get(chapter.number)`). 스크립트 주석에 "원본 번호 상태에서 한 번만 실행하라"고
경고가 붙어 있는데, 이미 재번호된 데이터에 다시 실행되면서 오버라이드가 통째로 밀렸다.

## 구현

### Part A. 경로를 데이터로 못박기
- `scripts/curriculum-path.json` 신설: 65개 챕터 id를 학습 순서로 나열 + **각 챕터가 왜 거기 있는지(`why`)**.
  `why`는 장식이 아니라 다음 편집자가 순서를 옮기기 전에 읽어야 할 근거다.
- `scripts/apply-curriculum-path.mjs`: 이 파일대로 `number` / `curriculumOrder` / `curriculumTrack` /
  `prerequisiteChapterIds`만 다시 계산한다. **본문·`level`은 건드리지 않는다.**
- `curriculumTrack`을 **`level`에서 파생**시켜, 둘이 다시 어긋날 수 없게 만들었다(기존 21건 불일치 해소).

### Part B. 오버라이드를 id로 재고정 (근본 원인 수리)
- 오버라이드는 `number: N` 키를 쓰지만 그건 **원본 번호**이고, 챕터 id `chapter-NN`이 그 번호를 그대로 보존한다.
  가설을 65/65로 검증한 뒤 **id 기준으로 재적용**했다.
- 복구된 필드: `goal` · `scenario` · `dialogue` · `realLifeTask` · `checkpoints` · `exitTask`.
  → **36개 챕터가 자기 부제를 되찾았다.**

## 회귀 방지
- `scripts/validate-curriculum-path.mjs` → `lint:content`에 연결. 난이도가 뒤로 가거나, track이 level과
  어긋나거나, 번호가 1..65가 아니면 **빌드가 실패한다**.
- `scripts/curriculum-path.test.js` (16): 전 챕터 1회씩 등장 / `why` 필수 / 난이도 단조 / 과거형이
  간접화법보다 앞 / id 안정성 / 오버라이드 id 정합 / 누락·중복·미지 챕터 거부.
- TDD로 작성해 **적용 전 RED 31건**(난이도 하강 + track 불일치)을 확인한 뒤 구현했다.

## 하지 않은 것 / 주의
- `level` 값 자체는 재판정하지 않았다(내용 난이도는 저자 판단 존중). 순서만 그에 맞췄다.
- 기존 테스트 2건이 `byNumber(N)`로 본문을 고정하고 있어 **id 기준으로 변경**했다. 표시 번호는 학습 위치라
  경로가 바뀌면 움직인다 — 본문 검증은 항상 id로 고정할 것.
- **저장된 진행도는 안전하다**: id 기준으로 저장되고 id는 하나도 바뀌지 않았다.
  다만 계정 로그인이 없어 진행도는 브라우저 localStorage에만 있으므로, 기기를 바꾸면 새 사용자로 보인다
  (백업/복원이 유일한 이전 경로 — Guide의 backup 카드).
- `apply-curriculum-structure.mjs`는 손대지 않았다(grammar.json 로마자 드리프트 버그가 남아 있어 실행 금지).
  순서 관련 작업은 앞으로 `apply-curriculum-path.mjs`가 담당한다.
