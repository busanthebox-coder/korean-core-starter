# S1 — 한 줄 경로: 표시 순서를 레벨·문법 의존 순으로

규모: 중(데이터 중심, UI 변경 최소). 의존 없음. **트랙 최우선 — 다른 모든 추천이 이 순서를 딛는다.**
목표 한 줄: "다음 챕터"를 따라가기만 하면 A1→A2→B1→B2→C1이 문법 의존 순으로 이어지게 만든다.

## 실측 근거 (2026-07-20)
- 표시 순서(= `chapters` 정렬 = "Next up" 추천 순서)가 11과(A1) 직후 B1 다섯 개(47·24·13·26·15)로 점프.
- `curriculumSortValue()` = `chapter.curriculumOrder || chapter.number`. 이 `curriculumOrder`가
  `scripts/apply-curriculum-structure.mjs` + `scripts/curriculum-*.json`에서 와서 레벨과 무관하게 뒤섞임.
- 챕터 번호는 표시 순서와 이미 무관하므로(40=과거형이 A2 앞줄) 번호는 신뢰 대상이 아니다 — 정렬만 고친다.

## 구현

### Part A. 목표 순서 확정 (데이터 파일로 체크인)
1. `scripts/curriculum-path.json` 신설 — **전체 65개 챕터 id의 명시적 순서 배열**. 생성 규칙:
   - 1차 키: 레벨 (A1 → A2 → B1 → B2 → B2/C1 → C1).
   - 2차 키(레벨 내부): **문법 의존 순**. A2 내부 확정 순서(감사 근거로 제안 — 실행자는 각 챕터 grammarNotes의
     선행 요구를 실측해 검증 후 조정, 조정 시 근거 기록):
     과거형(40) → 미래·의지(29) → 의문사(18) → 숫자·시간(31) → 세기(14) → 묘사(20) → 비교(33) →
     불규칙(12) → 부정 심화(16) → 제안(23) → 진행(46) → 순서·완료(35) → 방향·교통(42) → 나머지 A2.
     B1 내부: 존댓말 체계(32·17)를 B1 앞머리로(회화 목표와 직결), 간접화법(36)은 과거형+인용 표현 뒤.
   - 동률은 기존 번호 순.
2. 규칙 검증 스크립트 `scripts/validate-curriculum-path.mjs`:
   - 65개 전부 존재·중복 없음 / **레벨 단조 증가**(A1 뒤에 A1보다 낮은 레벨 없음, B2/C1·C1은 말미) /
   - 각 챕터의 grammarNotes가 참조하는 문법(grammarIds)이 경로상 **앞선 챕터에서 이미 등장**했는지 검사
     (완전 위상정렬은 과설계 — 위반 목록 경고 출력까지만, 실패 기준은 레벨 단조성만).
   - lint-content에 위임 호출 추가.

### Part B. 정렬 적용
1. `curriculumSortValue()`가 `curriculum-path.json`의 인덱스를 1순위로 쓰도록 변경
   (경로에 없는 챕터는 기존 로직 폴백 — 미래 챕터 추가 안전).
   적용 방식은 빌드 타임에 `course.chapters[].pathOrder` 필드 주입(런타임 json import 추가 없음, boot 크기 +미미).
2. "Next up"·`firstChapterOfLevel`·Learn 레벨 그룹핑(learnGroups)이 새 순서를 자동 상속하는지 확인 —
   상속된다면 코드 변경 없음(확인만 기록), 안 되면 해당 소비처 수정.
3. **주의: 기존 사용자 진행도는 id 기준이라 안전**하지만, "Next up"이 갑자기 바뀌는 사용자가 생긴다
   (예: B1을 이미 하나 끝낸 사용자). 이건 버그가 아니라 수정의 목적 — 완료 기록에 명시만.

### Part C. 표시 라벨
- 챕터 카드·레슨 헤더의 "Chapter N"은 유지하되, 경로 위치를 별도 표기: `A2 · 3/24` 형태
  (레벨 내 몇 번째인지 — pathOrder에서 파생, 저장 없음). 번호와 순서의 불일치가 주는 혼란을 라벨이 흡수.

## 수용 기준
1. 표시 순서가 레벨 단조 증가(자동 검증 스크립트 green). 11과 다음이 A2 챕터.
2. 신규 사용자 "Next up" 경로 추적 E2E: 1과부터 "다음"만 따라가면 65개를 레벨 순으로 통과.
3. 기존 진행도(완료 챕터 셋) 보존 확인 — localStorage 시드 후 순서 변경 전후 진행률 동일.
4. 테스트 green + build + lint:content(경로 검증 포함). 브라우저 QA(375px): Learn 그룹·"Next up"·`A2 · 3/24` 라벨.

- 챕터 번호·id 변경, 콘텐츠 이동. 완전한 문법 위상정렬 엔진(과설계 — 명시적 순서 배열이 정답).
- 잠금 도입(순서는 추천이지 강제가 아니다 — 아무 챕터나 먼저 여는 자유 유지).
