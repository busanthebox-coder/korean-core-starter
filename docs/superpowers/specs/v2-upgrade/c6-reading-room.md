# C6 — 읽기 자료실 (레벨별 장문 Graded Reader)

콘텐츠 트랙. 규모: 대. 의존: WS1 이후 권장(신규 데이터를 분할 체계에 넣기 위해 — 미완이면 core에 임시 포함 가능한 크기).
목표 한 줄: 챕터의 짧은 지문을 넘어, 레벨에 맞는 "진짜 읽을거리" 20편을 탭-글로스와 함께 제공한다.

## 배경 (실측)
- 챕터 readingText는 65과 전부 있으나 짧다(챕터 문법 시연용). "읽기 체력"을 기르는 장문이 없다.
- 사전 인덱스(3,768 headword)가 있으므로 **탭하면 뜻이 뜨는 글로스**를 사전 연동으로 만들 수 있다.

## 콘텐츠 설계 — 20편 (레벨당 5편)

| 레벨 | 길이(한글 기준) | 문체 | 주제 후보(각 레벨에서 5편 선택) |
|---|---|---|---|
| A1 | 100~200자 | 해요체, 단문 위주 | 자기소개 글 / 하루 일과 일기 / 가족 소개 / 문자 대화(약속 잡기) / 좋아하는 음식 |
| A2 | 250~450자 | 해요체, 연결어미 활용 | 주말 여행 일기 / 맛집 후기 / 길 찾기 실패담 / 계절과 날씨 이야기 / 쇼핑 실수담 |
| B1 | 450~700자 | 해요체+간접화법 | 친구 조언 편지 / 한국 생활 블로그(집 구하기) / 건강 습관 수필 / 직장 첫 출근기 / 명절 경험담 |
| B2 | 700~1000자 | 문어체 혼용(-다체 일부) | 짧은 칼럼(디지털 생활) / 전통과 현대 에세이 / 가벼운 서사(짧은 이야기) / 인터뷰 기사체 / 안내문+해설 |

편당 구조(`scripts/readers-src/reader-XX.json`):
```json
{
  "id": "reader-a1-01", "level": "A1", "title": "제 하루", "titleEn": "My Day",
  "genre": "diary", "body": "…(문단 배열: ["문단1", "문단2"])",
  "bodyTranslation": ["…"],                  // 문단 대응 영어(접이식으로 노출)
  "comprehensionQuestions": [                 // 4문항: 사실 2 + 추론 1 + 어휘 1
    {"type":"multipleChoice","prompt":"...","options":[...],"correct":"...","explanation":"..."}
  ],
  "summaryPrompt": "이 글을 두 문장으로 요약해 보세요.",   // WS6 완료 시 쓰기 저장 연동
  "newWords": ["id or headword", ...]         // 글로스 매칭 실패 대비 수동 보강(≤5개)
}
```

### 언어 통제 (생성 스펙의 핵심 — 리뷰에서 엄격 검증)
1. **문법 범위**: 그 레벨까지의 챕터에서 가르친 문법만. 생성 스펙에 레벨별 허용 문법 리스트를 동봉
   (chapters의 grammarFocus/grammarNotes 제목에서 스크립트로 추출해 첨부).
2. **어휘 커버리지**: 본문 어절의 **≥85%가 사전 headword와 매칭**되어야 한다(측정 스크립트 아래).
   미달이면 본문을 사전 어휘로 재작성. 나머지 15%도 고빈도 일상어만.
3. 고유명사는 한국 실정에 맞되 단순하게(민수·수진·부산·서울). 문화 요소는 자연스럽게 녹임(설명조 금지).

## 글로스(탭하면 뜻) 설계
- `src/lib/gloss.js`: 어절 → 사전 매칭.
  1. 어절 그대로 headword 일치 → 매치.
  2. 조사 스트립 후 일치(WS7의 조사 목록 재사용 — WS7 미완이면 이 WS에서 먼저 만들고 WS7이 가져다 씀. 중복 구현 금지).
  3. 용언 활용 → forms 역인덱스(words 495개의 forms 15종 값 → entryId 맵을 빌드 타임에 생성)로 일치.
  4. 실패 → 밑줄 없음(무동작. 오매칭보다 무동작이 낫다).
- UI: 매칭 어절에 점선 밑줄, 탭하면 작은 팝오버(hangul·뜻·품사 + "사전에서 보기" → EntryDetail).
  같은 화면에서 하나만 열림. 모바일 터치 우선.
- **커버리지 측정 스크립트** `scripts/check-reader-coverage.mjs`: 편별 매칭률 출력, <85%면 exit 1.
  (이 스크립트가 글로스 로직과 같은 매칭 코드를 쓰도록 gloss.js를 node에서도 import 가능하게 작성.)

## UI 배치
- Learn 탭 챕터 목록 아래 "Reading Room" 섹션(레벨 탭 → 카드 목록: 제목·장르·길이·완료 체크).
- 리더 화면: 본문(문단 간격 넉넉히, Gowun Batang) → 문단별 번역 접이식 → 이해 문항 4개 →
  요약 쓰기(textarea, WS6 있으면 저장) → 완료 버튼(`kcs.readers-v1`에 기록: {id: {readAt, score}}).
- 로마자 토글은 본문에 적용하지 않는다(장문에 로마자는 반훈련 — 글로스로 충분).

## 파이프라인
1. 레벨별 허용 문법·어휘 리스트 추출 스크립트 → 생성 스펙에 동봉.
2. 배치 에이전트 4개(레벨당 1개, 5편씩) → **리뷰 2중**: (a) 언어 리뷰(문법 범위 위반·저빈도어·부자연) +
   (b) 커버리지 스크립트 기계 검증 → 수정 → 적용.
3. build-app-data에 readers 병합(WS1 완료 시 core 청크 또는 별도 `app-readers.json` — 20편 raw ~60KB 추정이라 core 포함 무방).

## 신규 키·연동
- `kcs.readers-v1` → WS3 BACKUP_KEYS + 00-README 표에 추가. WS5 있으면 완료 시 recordActivity.

## 테스트·수용 기준
1. 20편 전부 커버리지 ≥85%(스크립트 로그). 2. 글로스 매칭 단위 테스트(직일치·조사 스트립·활용 역인덱스·실패 무동작).
3. 리더 화면 E2E 1회(글로스 팝오버·문항·완료 기록). 4. 이해 문항 정답 유일성(C2의 validate 스크립트 재사용).
5. 전 테스트 green + build (+WS1 완료 상태면 사이즈 가드 통과).
